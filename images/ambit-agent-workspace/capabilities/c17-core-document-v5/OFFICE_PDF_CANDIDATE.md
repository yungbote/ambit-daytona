# Office PDF source candidate

This source adds `--office-pdf-jsonl --nonce …` to the existing document helper. It converts admitted DOCX, PPTX and XLSX packages into a source-bound PDF through the same LibreOffice invocation, private directories, framed input, process-group owner and terminal arbiter. The existing DOCX paginated API remains available to its existing callers. The compatibility `convertDocxToPdf` wrapper can be retired only after those callers migrate; it delegates to the single Office converter.

The Office result is a derived view. Original source bytes/hash and the exact PDF bytes/hash remain separate. PDF metadata may vary between conversions, so its hash identifies the actual derivative rather than promising deterministic conversion. Structured workbook reads and ordinary programs remain independent.

`locks/office-pdf-interface.lock.json` is a prospective source contract, copied exactly into the backend. Its `candidate-ready` value identifies a complete protocol description, not an admitted runtime, image certification or deployment. Existing `document-render-interface.lock.json`, all historical certification records and image evidence remain unchanged. Their source hashes do not certify this modified helper. A future image must install the new policy/lock, qualify the modified helper, bind its exact source/image identity and advertise the new Office interface before host currentness can admit it. Do not relabel older image evidence or infer an Office interface from the presence of LibreOffice.

The current ordinary file-tools image contains LibreOffice and Office libraries but lacks the `core-document-v5` helper and private structural Python runtime. The new API remains dormant: upload-reader/executor wiring and runtime adoption are not included. The eventual caller belongs in the host execution engine's existing Run/grant/workspace selection; it passes an optional conversion closure to the attachment reader. No existing workspace means the optional PDF representation is unavailable. This source does not provision a workspace automatically.

Package admission retains the existing restricted XML, ZIP expansion, macro, embedded active-content and external-relationship policy. Password-protected packages, external relationships and embedded package/OLE parts are rejected. Presentation charts that require embedded workbook packages therefore remain outside this admitted subset. Charts stored directly in an XLSX package were exercised locally. Rendering follows LibreOffice print layout; it is not a claim that all cells, hidden sheets, formulas, speaker notes or off-print-area content appear in the PDF.

Source verification includes the shared DOCX tests, Office media/package mismatch cases, ordered chunk/source/digest admission, cancellation and private-root cleanup. Local real LibreOffice conversion used generated two-page DOCX, two-slide PPTX and a two-sheet XLSX with a formula, merged cells and chart. Text readback verified the two document pages, both slide titles, second sheet and calculated total 30; original hashes remained unchanged. That local test used the ordinary image's Python through the existing process-group implementation, not the unpublished specialist runtime. It is not deployment or browser/model acceptance. Evidence is task-scoped at `/var/tmp/ambit-office-render-r2-20260909/`.
